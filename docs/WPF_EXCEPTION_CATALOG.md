## How to read this (the 11ak contract)

- **VAML-facing=true** means the exception is part of the application-facing WPF UI surface
  and MUST be mapped to a VAML exception type derived from the common `vaml::exception` base,
  so user code written for a WPF `catch (InvalidOperationException)` / `catch (XamlParseException)`
  keeps compiling against VAML.
- **VAML-facing=false** (XPS/Reach/print/task-tooling) is NOT expected to be caught cross-language;
  it is recorded here for completeness, not scheduled for a VAML class.
- **Known base families** (the .NET framework catch types at the bottom) are recorded statically;
  they are not `*.cs` in the repo. The catch-all `vaml::exception` base must serve them.

## Notable members carried by VAML-facing exceptions

The observable contract a VAML exception class must honor is the **name** + the **distinct
public members** (so WPF `catch` blocks / member access keep compiling). The .NET base
**type identity** (e.g. deriving from `System.InvalidOperationException`) cannot be mirrored
in C++ — but the catchable cross-language surface is the name + members, which C++ CAN match
exactly by declaring `class InvalidOperationException : vaml::exception` and
`class ResourceReferenceKeyNotFoundException : InvalidOperationException`. The base-type
column above is informational (which .NET family WPF derives from), recorded so the shim knows
what a user is likely to `catch`.
